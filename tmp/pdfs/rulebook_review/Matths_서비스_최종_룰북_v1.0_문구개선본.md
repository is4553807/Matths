# Matths 서비스 최종 룰북 v1.0

- 문서 상태: 정책 기준본
- 기준일: 2026-07-30
- 적용 범위: 29일 유료 패키지, 30일 페이백, 출석, 배치고사, 공식 모의고사, MMR, Sub Ranking, Main Ranking, Rank Takeover, 추가 학습권, 랭크 상점, 결제 제한, 부정행위, 운영
- 우선 원칙: 유료로 구매한 29일 이용권은 랭킹 결과와 무관하게 전부 보장한다.

> 이 문서는 제품·운영·개발을 위한 정책 기준이다. 결제, 페이백, 미성년자 동의, 개인정보, 약관 문구는 출시 전 별도 법률 검토를 거쳐야 하며 실제 약관과 화면 문구가 이 규칙과 일치해야 한다.

---

## 0. 문서 사용법

### 0.1 규칙의 강도

- **반드시**: 시스템과 운영자가 예외 없이 지켜야 하는 규칙
- **원칙적으로**: 정해진 장애·이의신청 절차에서만 예외를 허용하는 규칙
- **권장**: 출시 후 지표에 따라 조정할 수 있는 초기값
- **출시 전 확정**: 현재 문서에서 방향만 정해졌고 운영 파라미터가 아직 결정되지 않은 항목

### 0.2 규칙 충돌 시 우선순위

1. 법령과 확정된 이용약관
2. 이 룰북의 결제·권리 보호 원칙
3. 이 룰북의 랭킹·페이백 상태 전이
4. 관리자 운영 매뉴얼
5. 화면 문구와 마케팅 소재

화면이나 광고가 룰북보다 유리한 조건을 약속한 경우 운영자가 임의로 불리하게
해석하지 않고, 약속의 범위와 법률 검토 결과에 따라 사용자 보호 방향으로 처리한다.

### 0.3 시간 기준

- 서비스의 하루는 대한민국 표준시(KST) 00:00:00부터 23:59:59까지다.
- 모든 결제일, 출석일, 24시간 매치 마감, 시즌 정산은 서버 시간을 기준으로 한다.
- 클라이언트 기기 시간은 화면 표시용일 뿐 권리·잔액 판정에 사용하지 않는다.

## 1. 서비스 핵심 원칙

### 1.1 권리와 경쟁의 분리

Matths는 돈을 내고 산 이용권과 랭킹에서 사용하는 도전 자산을 분리한다.

- `paidAccessDays`: 결제로 보장되는 29일
- `refundChallengeDays`: Sub Ranking과 페이백 조건에 쓰는 도전 일수
- `bonusAccessDays`: 페이백 후 Main Ranking에서 쓰는 추가 학습권
- `lockedDays`: 진행 중인 Rank Takeover 때문에 잠긴 일수

랭킹전에서 패배해도 `paidAccessDays`는 줄지 않는다.

### 1.2 한 사용자, 한 활성 랭킹

사용자 이름은 같은 시점에 Sub Ranking과 Main Ranking 중 한 곳에만 표시한다.

```text
activeRanking ∈ {SUB, MAIN}
```

- `activeRanking = SUB`: Sub에만 이름·티어·순위·MMR 표시
- `activeRanking = MAIN`: Main에만 이름·티어·순위·MMR 표시
- 비활성 카드에는 사용자의 실제 순위를 표시하지 않는다.

### 1.3 한 사용자, 한 실력 MMR

Sub와 Main에 별도 MMR을 만들지 않는다. 공식 모의고사로 계산되는
`skillMMR` 하나를 웹과 앱이 공동으로 사용한다.

### 1.4 두 종류의 랭킹 변화

1. **공식 모의고사 MMR**: 장기 실력을 평가하고 매주 랭킹을 재정렬한다.
2. **Rank Takeover**: 주중 비동기 1대1 도전으로 공개 순위를 즉시 바꾼다.

Rank Takeover는 MMR을 직접 바꾸지 않는다. 월요일 정산 때 MMR이 다시 장기 기준이 된다.

### 1.5 투명한 동기부여

Main Ranking은 성취감을 주는 시각적 위계를 사용할 수 있다. 그러나 다음은 금지한다.

- 달성하지 않은 환불 가능성을 확정적으로 표현
- 남은 시간이나 경쟁자를 허위로 표시
- Sub 사용자를 모욕하거나 수치심을 유발하는 문구
- 재결제가 필요한 것처럼 오인시키는 숨은 조건
- 이용권이 남아 있는데 소멸을 암시하는 압박

| 연습 응시 | 공식 선택 외 추가 응시로, 학습 기록에는 남지만 MMR에는 반영되지 않는 시험 |

| 공개 순위 | 현재 활성 랭킹 풀에서 사용자에게 표시되는 순서 |
| Rank Takeover | 같은 랭킹의 상위 자리를 대상으로 하는 비동기 1대1 도전 |
| 방어자 | 시스템에 의해 도전 대상이 된 기존 상위 사용자 |
| 도전자 | 일수를 잠그고 Rank Takeover를 신청한 사용자 |
| 랭크 방어권 | 일정 시간 신규 방어 매칭 대상에서 제외되는 Main Ranking 아이템 |
| 시즌 | 랭킹 기록·배지·보상을 집계하는 운영 기간 |

## 3. 사용자와 운영 역할

### 3.1 사용자

- 본인 계정으로 학습·시험·랭킹전에 참여한다.
- 결제·페이백 조건과 잔액 변화를 확인할 수 있다.
- 부정행위 의심 시 소명과 재심을 신청할 수 있다.
- 랭킹 표시용 이름·학교 정보는 허용된 범위에서 설정한다.

### 3.2 관리자

- 시험 일정, 문제지, 정답, 난이도 보정을 관리한다.
- 페이백·잔액 원장·매치 정산을 조회한다.
- 자동 판정이 보류한 부정행위와 이의신청을 처리한다.
- 사용자 잔액을 직접 고칠 때 사유와 감사 로그를 남긴다.

### 3.3 시스템

- 서버 시간과 원장에 따라 권리·잔액·랭킹을 판정한다.
- 중복 요청과 스케줄러 재실행에도 같은 거래를 한 번만 반영한다.
- 웹과 앱에 동일한 랭킹 결과를 제공한다.
- 자동 제재만으로 영구 정지를 확정하지 않는다.

## 4. 핵심 데이터와 불변식

### 4.1 권장 필드

| 필드 | 형식 | 의미 |
|---|---|---|
| `paidAccessDays` | 0 이상의 정수 | 결제로 보장되는 남은 유료 이용일 |
| `refundChallengeDays` | 0 이상의 정수 | Sub Ranking 도전 잔액 |
| `bonusAccessDays` | 0 이상의 정수 | Main Ranking 추가 학습권 |
| `lockedDays` | 0 이상의 정수 | 진행 중 매치에 잠긴 잔액 |
| `streakDays` | 0 이상의 정수 | 현재 연속 학습일 |
| `skillMMR` | 0 이상의 정수 | 공통 실력 레이팅 |
| `rankTier` | 열거형 | MMR 구간에 따른 티어 |
| `ladderPosition` | 양의 정수 또는 `null` | 활성 랭킹의 공개 순위 |
| `activeRanking` | `SUB` 또는 `MAIN` | 이름이 표시되는 랭킹 |
| `refundCompletedAt` | 시각 또는 `null` | 해당 주기 페이백 완료 시각 |
| `mainRankingEnteredAt` | 시각 또는 `null` | Main 최초 진입 시각 |
| `rankShieldUntil` | 시각 또는 `null` | 신규 방어 매칭 제외 종료 시각 |

### 4.2 필수 불변식

1. 잔액 필드는 음수가 될 수 없다.
2. `paidAccessDays`는 Rank Takeover 또는 랭크 상점으로 차감할 수 없다.
3. 한 결제 건은 최대 한 번만 페이백할 수 있다.
4. 한 사용자는 동시에 한 Rank Takeover만 진행할 수 있다.
5. 한 사용자는 두 공개 랭킹에 동시에 나타날 수 없다.
6. 매칭 참가자의 `activeRanking`은 반드시 같다.
7. 잔액 증감에는 원장 기록과 고유 멱등 키가 반드시 존재한다.
8. 매치 결과와 잔액 정산은 분리해서 부분 성공시키지 않는다.
9. 탈퇴 후 통계 전용 프로필은 공개 랭킹과 자동 매칭에서 제외한다.

### 4.3 잔액 원장

모든 증감은 다음 정보를 남긴다.

| 항목 | 예 |
|---|---|
| 거래 유형 | `PACKAGE_ISSUE`, `MATCH_LOCK`, `MATCH_TRANSFER`, `MATCH_BURN`, `REFUND_CONVERT`, `DAILY_USE`, `SHOP_PURCHASE`, `ADMIN_ADJUST` |
| 사용자 | 잔액 소유자 |
| 결제 주기 | 관련 `AccessCycle` |
| 매치·주문 | 원인이 된 외부 ID |
| 변화량 | `+3`, `-6` |
| 변경 후 잔액 | 거래 적용 직후 값 |
| 멱등 키 | 동일 이벤트 중복 반영 방지 키 |
| 사유 | 사용자에게 보여 줄 설명 |
| 시각 | 서버 처리 시각 |

## 5. 사용자 상태 흐름

### 5.1 상태

| 상태 | 설명 |
|---|---|
| `NO_PACKAGE` | 활성 결제 주기가 없음 |
| `SUB_PLACEMENT` | Sub 소속이며 배치전 진행 중 |
| `SUB_ACTIVE` | Sub에서 실제 순위가 공개됨 |
| `REFUND_REVIEW` | 30일 조건 확인 또는 지급 처리 중 |
| `MAIN_ACTIVE` | Main에서 경쟁하고 추가 학습권을 사용함 |
| `MAIN_SETTLING` | 학습권은 0이지만 잠금·매치 정산이 남음 |
| `FREE_INACTIVE` | 활성 이용권과 랭킹 참여가 없음 |
| `RESTRICTED` | 부정행위·계정 상태로 일부 기능 제한 |

### 5.2 정상적인 상태 전환

```text
NO_PACKAGE
  -> 패키지 결제
SUB_PLACEMENT
  -> 배치전 5회 완료
SUB_ACTIVE
  -> 30일 연속 학습 + 도전 일수 30일 이상
REFUND_REVIEW
  -> 페이백 지급 + 잔액 변환
MAIN_ACTIVE
  -> 추가 학습권 0, 잠금 또는 매치 존재
MAIN_SETTLING
  -> 모든 정산 완료
FREE_INACTIVE
  -> 새 패키지 결제
SUB_PLACEMENT 또는 SUB_ACTIVE
```

Placement 완료 이력은 계정 단위로 유지할 수 있다. 이미 Placement를 마친 사용자가
새 패키지를 구매하면 시즌 정책에 따라 `SUB_ACTIVE`로 바로 돌아갈 수 있다.

### 5.3 허용하지 않는 상태 전환

- Sub에서 페이백을 완료하지 않은 채 Main으로 바로 이동
- Main Ranking에 사용 가능한 잔액, 잠금 일수 또는 진행 중인 매치가 있는데 새 패키지 주문 생성
- 같은 결제 건에 페이백을 두 번 지급
- 진행 중인 매치를 남겨 둔 채 활성 랭킹 변경
- Sub와 Main 양쪽에 동시에 공개 순위 등록

## 6. 29일 패키지

### 6.1 이용권 지급

결제 승인이 완료되면 하나의 이용 사이클을 만들고 다음 항목을 지급한다.

```text
paidAccessDays = 29
refundChallengeDays = 29
bonusAccessDays = 0
lockedDays = 0
streakDays = 0
activeRanking = SUB
```

결제사의 Transaction ID를 고유 키로 사용해, 동일한 결제 Webhook이 다시 전송되어도
이용 사이클이 중복 생성되지 않도록 한다.

### 6.2 이용 기간

- 7월 1일에 결제하면 7월 1일부터 7월 29일까지 유료 이용 기간이 제공된다.
- 결제 시각에 따라 첫날을 부분 일수로 처리할 경우, 해당 기준을 구매 전에 명확히 안내한다.
- 랭킹 승패와 관계없이 유료 29일은 전부 보장한다.
- 계정 정지나 이용 제한은 약관상 근거와 사전 통지, 이의신청 절차를 갖춰야 한다.

### 6.3 Day 30 Access Pass

29일 유료 이용을 모두 사용한 뒤에도 30일 차 페이백 도전을 이어 갈 수 있는 사용자에게는,
30일 차 학습을 마칠 수 있도록 제한된 접근 권한인 Day 30 Access Pass를 제공한다.

- 목적: 30일 차 학습 및 출석 조건 완료
- 세부 이용 범위: 출시 전 확정
- 자동 개방 조건: 29일 유료 이용 완료 및 `refundChallengeDays >= 30`
- 일반 유료 이용권과 구분되도록 화면에 `Day 30 Access Pass`로 표시

## 7. 출석과 30일 페이백

### 7.1 학습일 인정 기준

로그인만으로는 출석이 인정되지 않는다. 하루를 유효 학습일로 인정하려면 다음 조건을 모두 충족해야 한다.

1. 지정된 문제 세트 또는 출석 인정 대상 모의고사를 완료한다.
2. 최소 유효 학습 시간을 채운다.
3. 답안 제출이 서버에 완료된다.
4. 비정상적으로 짧은 풀이 시간, 반복 새로고침, 자동화 의심 패턴이 없어야 한다.

최소 문제 수와 유효 학습 시간 기준은 출시 전에 확정한다.

### 7.2 연속 학습일

- 유효 학습일이 이어질 때마다 `streakDays`를 1씩 늘린다.
- 하루라도 누락되면 다음 유효 학습일에 `streakDays`를 1부터 다시 계산한다.
- 서버 장애로 학습을 완료할 수 없었던 사용자는 출석 복구 심사를 신청할 수 있다.
- 복구 여부는 해당 날짜의 학습 기록과 장애 기록을 근거로 판단한다.

### 7.3 페이백 자격 조건

다음 두 조건을 모두 충족해야 페이백 대상이 된다.

$$
Eligible = (streakDays \ge 30) \land (refundChallengeDays \ge 30)
$$

도전 일수가 30일을 넘어도 연속 학습 30일을 채우기 전에는 페이백을 받을 수 없다.

### 7.4 페이백 지급액

지급액은 해당 결제 건에서 실제로 승인되고 최종 정산된 금액을 초과할 수 없다.

```text
refundAmount = 실제 결제금액 - 이미 취소·환급된 금액
```

- 정가가 아닌 쿠폰·포인트 적용 후 실제 결제액을 기준으로 한다.
- 도전 일수가 60일이어도 결제액의 두 배를 지급하지 않는다.
- 결제 1건당 페이백은 한 번만 지급한다.

### 7.5 페이백 완료 후 잔액 전환

$$
bonusAccessDays = refundChallengeDays - 29
$$

예시:

```text
페이백 직전 refundChallengeDays = 60
정산 기준 차감 = 29
페이백 후 bonusAccessDays = 31
activeRanking = MAIN
```

잔액 전환과 Main Ranking 진입은 하나의 트랜잭션으로 처리한다.

### 7.6 페이백 조건 미달

- 구매한 29일 이용권은 그대로 사용할 수 있다.
- 추가 금액을 청구하지 않는다.
- 충족하지 못한 조건과 사유를 화면에 구체적으로 안내한다.
- 재구매가 허용되는 시점에 새 패키지를 구매하면 새로운 도전 주기가 시작된다.

## 8. 배치고사

### 8.1 운영 목적

- 사용자의 초기 실력 수준 파악
- 초기 MMR 변동 폭을 안정화할 표본 확보
- 학습 추천과 취약 영역 분석
- 신뢰도가 낮은 임시 순위의 과도한 노출 방지

### 8.2 Placement 규칙

- 신규 사용자의 초기 MMR은 1500이다.
- 첫 5회의 공식 모의고사를 Placement 기간으로 운영한다.
- 5회가 끝나기 전에는 랭킹 카드에 `Placement 진행 중 · n/5회`를 표시한다.
- 임시 순위는 공개하지 않는다.
- Placement 완료 이력이 있는 사용자가 다시 결제할 때 재응시를 요구할지는 시즌 정책으로 정한다.

### 8.3 Placement 기간의 MMR

Placement 기간에도 내부 MMR은 계속 갱신하되, 공개 순위는 5회가 끝난 뒤 확정한다.
이 기간에는 `K=48`을 적용한다.

### 8.4 일정상 충돌

공식 모의고사를 주 1회만 MMR에 반영하면 Placement 5회를 마치는 데 5주가 걸린다.
29일 패키지 안에서 Sub Ranking 순위를 공개하려면 출시 전에 다음 중 하나를 선택해야 한다.

1. 첫 주에 Onboarding 전용 Placement 5회 제공
2. 공식 모의고사와 별도의 Placement Session 운영
3. Placement 완료 전 제한된 임시 Sub Ranking 공개

정책 확정 전에는 시스템이 임의의 방식을 자동 적용하지 않는다.

## 9. Sub Ranking과 Main Ranking

### 9.1 랭킹 구분

| 항목 | Sub Ranking | Main Ranking |
|---|---|---|
| 대상 | 페이백에 도전 중인 사용자 | 페이백을 완료한 사용자 |
| 사용 잔액 | `refundChallengeDays` | `bonusAccessDays` |
| 실력 값 | 공통 `skillMMR` | 공통 `skillMMR` |
| 공개 순위 | Sub Ranking 참여자 안에서 계산 | Main Ranking 참여자 안에서 계산 |
| Rank Takeover | Sub Ranking 안에서만 | Main Ranking 안에서만 |
| 랭크 상점 | 사용 불가 | 사용 가능 |

### 9.2 Sub Ranking 진입

- 새 이용 사이클이 시작되면 `activeRanking = SUB`다.
- 페이백 완료 전에는 Main Ranking에 이름을 표시하지 않는다.
- 30일이 지나도 조건을 충족하지 못하면 Main Ranking으로 자동 이동하지 않는다.

### 9.3 Main Ranking 진입 조건

다음 조건을 모두 충족해야 한다.

1. `streakDays >= 30`
2. 30일 차 판정 시점에 `refundChallengeDays >= 30`
3. 페이백 지급이 완료되었거나 최종 확정 상태
4. 진행 중이던 Sub Rank Takeover가 모두 정산된 상태

진입 처리:

```text
activeRanking = MAIN
mainRankingEnteredAt = now
subLadderPosition = null
mainLadderPosition = Main Ranking 참여자의 skillMMR를 기준으로 계산
```

기존 `skillMMR`와 `rankTier`는 그대로 유지한다.

### 9.4 Tier 변경과 Ranking 이동의 구분

- Tier 하락: MMR 구간이 낮아지는 것
- Ranking 이동: Main에서 Sub로 소속 랭킹이 바뀌는 것

두 조건은 서로 다르다. v1.0에서는 Main→Sub 자동 이동 여부가 출시 전 확정 항목이다.
정책이 확정되기 전에는 Tier가 낮아져도 사용자를 Sub Ranking으로 자동 이동시키지 않는다.
새 패키지를 구매해 새 페이백 주기를 시작할 때만 Main에서 Sub로 이동한다.

## 10. 대시보드 랭킹 카드

### 10.1 기본 표시 원칙

- Dashboard에 Sub와 Main 카드를 항상 함께 표시한다.
- 현재 참여 중인 카드만 활성 스타일로 강조한다.
- 활성 카드에만 사용자의 이름과 실제 순위를 표시한다.
- 비활성 카드에는 다음 목표와 현재 상태만 안내한다.

### 10.2 Placement 진행 중

```text
Sub Ranking: Placement 진행 중 · 3/5회
Main Ranking: Placement 진행 중 · 3/5회
```

임시 순위 대신 다음 공식 모의고사 일정과 남은 Placement 횟수를 안내한다.

### 10.3 Sub Ranking 활성 상태

Sub 카드에 표시할 정보:

- 본인 이름
- 현재 순위
- 티어와 MMR
- 다음 달성 목표
- 최근 MMR 증감

Main 카드에는 다음 안내를 표시한다.

> **Main Ranking에 입장하려면 Sub Ranking 목표를 완료하세요.**
>
> 연속 학습 30일을 완료하고, 30일 차에 도전 일수를 30일 이상 보유하면 페이백을 받은 뒤 Main Ranking에 진입할 수 있습니다.

조건별 진행 상황:

- `연속 학습 18/30일`
- `환불 도전 일수 31/30일`
- 조건 충족 여부 아이콘
- 페이백 예상 금액
- 지급 방식과 예상 처리 시간

### 10.4 Main Ranking 활성 상태

Main 카드에 표시할 정보:

- 본인 이름, 실제 순위, 티어, MMR
- `MAIN RANKER` 배지
- Main 진입일
- 시즌 최고 순위
- 남은 추가 학습권

Sub 카드에는 다음 안내를 표시한다.

> **Main Ranking에 이름을 올린 플레이어입니다.**
>
> 현재 Main Ranking에서 경쟁 중입니다. Main Ranking에서 강등되면 Sub Ranking으로 이동합니다.

자동 강등을 사용하지 않는 시즌에는 강등 문구를 노출하지 않는다. 대신
`새 페이백 주기를 시작하면 Sub Ranking으로 이동합니다`라고 안내한다.

### 10.5 접근성과 정확한 안내

- 색상만으로 활성·잠금 상태를 구분하지 않는다.
- Screen Reader용 상태 문구를 제공한다.
- 남은 일수와 달성 조건은 서버의 최신 값을 기준으로 표시한다.
- 사용자 이름이 비활성 카드나 오래된 Cache 목록에 남지 않도록 한다.

## 11. 공식 모의고사 운영

### 11.1 일요일 세 개의 Time Slot

- 매주 일요일 KST 15:00, 18:00, 21:00의 세 Time Slot 운영을 권장한다.
- A/B/C는 난이도를 맞춘 서로 다른 문제 세트다.
- 사용자는 세 Time Slot 중 하나를 공식 응시(Official Attempt)로 미리 선택한다.
- 나머지 Time Slot에 응시한 기록은 연습 응시(Practice Attempt)로만 저장한다.
- 시험이 끝난 뒤 최고 점수를 공식 기록으로 고르는 방식은 허용하지 않는다.

### 11.2 문제 세트 난이도 동등성

- 단원 비율 동일
- 문항 수와 배점 동일
- 목표 난이도 동일
- 각 문항에 사전 난이도 계수 부여
- 같은 문항 재사용 금지
- 충분한 표본이 쌓이면 정답률과 변별도를 기준으로 난이도를 다시 보정

### 11.3 보정 점수

각 문항의 난이도를 반영한 보정 점수(`calibratedScore`)를 공식 점수로 사용한다.

동점자 순위 결정 기준:

1. 보정 점수 합계
2. 고난도 문항 정답 수
3. 정답 문항에 사용한 실제 풀이 시간
4. 앞선 기준까지 모두 같으면 공동 순위

풀이 시간은 앞선 기준까지 같은 사용자끼리만 비교한다.

### 11.4 주간 결과 반영

일요일 마지막 Time Slot이 끝나면 다음 순서로 처리한다.

1. A/B/C 문제 세트의 정답과 오류 수정 사항을 확정한다.
2. 공식 응시(Official Attempt)만 해당 주간의 MMR 계산 대상에 포함한다.
3. 난이도를 반영한 보정 점수를 계산한다.
4. 동점 처리 기준에 따라 주간 순위를 정한다.
5. MMR을 갱신한다.
6. 티어를 갱신한다.
7. 월요일 00:00에 Sub와 Main을 각각 MMR 순으로 다시 정렬한다.

## 12. MMR 계산

### 12.1 기호 정의

| 기호 | 뜻 |
|---|---|
| `N` | 해당 주간 공식 응시자 수 |
| `r_i` | 해당 주간 사용자 `i`의 순위 |
| `S_i` | 사용자 `i`의 실제 성과값 |
| `MMR_i` | 정산 전 사용자 `i`의 MMR |
| `E_ij` | 사용자 `i`가 `j`보다 높은 순위를 기록할 예상 확률 |
| `E_i` | 사용자 `i`의 전체 예상 성과값 |
| `K` | 사용자 상태별 MMR 변동 계수 |

### 12.2 실제 성과값

$$
S_i = \frac{N - r_i}{N - 1}
$$

- 1위는 1.0
- 최하위는 0.0
- 중간 순위는 약 0.5
- 공동 순위는 해당 순위 구간의 평균값을 `r_i`에 적용한다.
- 공식 응시자가 1명뿐이면(`N = 1`) MMR 반영을 보류한다.

### 12.3 상대별 예상 우위 확률

$$
E_{ij} = \frac{1}{1 + 10^{(MMR_j - MMR_i)/400}}
$$

MMR이 같으면 서로 앞설 확률은 0.5다.

### 12.4 전체 예상 성과값

$$
E_i = \frac{1}{N - 1}\sum_{j \ne i} E_{ij}
$$

### 12.5 MMR 증감

$$
\Delta MMR_i = K(S_i - E_i)
$$

$$
MMR_i^{new} = \max(0,\ round(MMR_i^{old} + \Delta MMR_i))
$$

중간 계산값은 충분한 소수점 정밀도로 유지하고, 최종 MMR만 정수로 반올림한다.

### 12.6 K Factor

| 사용자 구분 | K |
|---|---:|
| 첫 5회 Placement | 48 |
| 일반 | 24 |
| 정산 전 MMR 2000 이상 | 16 |

조건이 겹치면 Placement의 `K=48`을 우선한다.

### 12.7 계산 예시

공식 응시자가 100명이고 사용자 A가 20위라면:

$$
S_A = \frac{100 - 20}{100 - 1} = \frac{80}{99} \approx 0.8081
$$

A의 전체 예상 성과값이 0.55이고 일반 사용자(`K=24`)라면:

$$
\Delta MMR_A = 24(0.8081 - 0.55) \approx 6.1944
$$

반영 전 MMR이 1600이라면 새 MMR은 1606이다.

### 12.8 Tier 기준

| MMR | 티어 |
|---:|---|
| 0~1199 | Bronze |
| 1200~1399 | Silver |
| 1400~1599 | Gold |
| 1600~1799 | Platinum |
| 1800~1999 | Diamond |
| 2000~2199 | Master |
| 2200 이상 | GOAT |

MMR과 Tier는 하나의 트랜잭션으로 함께 저장한다.

## 13. Rank Takeover 공통 규칙

### 13.1 매치 진행 방식

Rank Takeover는 실시간 대전이 아니라, 각 사용자가 정해진 시간 안에 따로 응시하는
비동기 1:1 매치다.

```text
CREATED -> MATCHED -> READY -> IN_PROGRESS -> SUBMITTED
        -> RESOLVED -> SETTLED
```

오류나 부정행위 검토가 필요하면 `HELD`, 서버 문제로 취소하면 `CANCELLED` 상태를 사용한다.

### 13.2 Challenge 신청 절차

1. 도전자가 원하는 순위 범위를 선택한다.
2. 서버에서 필요한 일수와 사용 가능한 잔액을 확인한다.
3. 도전에 사용할 일수를 잠금 처리한다.
4. 같은 Ranking 안의 조건을 충족한 후보 중 한 명을 무작위로 선택한다.
5. 도전자와 방어자 모두에게 알림을 보낸다.
6. 매치가 성립되면 양쪽 모두 24시간 안에 시험을 시작해야 한다.
7. 제출 또는 마감 후 승패를 결정하고 순위와 잔액에 반영한다.

### 13.3 Challenge Range와 필요 일수

| 구간 | 대상 | 잠금 일수 |
|---|---|---:|
| 1-Step Challenge | 바로 위(1계단 상위) | 2일 |
| 2-3 Step Challenge | 2~3계단 상위 | 3일 |
| High-Rank Challenge | 4~7계단 상위 | 6일 |

- 최대 7계단 상위까지 도전할 수 있도록 권장한다.
- 참여자가 적으면 같은 Tier의 유사 Percentile 구간으로 대상을 넓힐 수 있다.
- 사용 가능한 잔액이 부족하면 매치를 만들지 않는다.

### 13.4 매칭 후보 조건

- 현재 참여 중인 Ranking이 같음
- 선택한 Challenge Range 안에 있음
- 다른 Rank Takeover를 진행 중이지 않음
- Rank Shield가 활성화되어 있지 않음
- 이전 경기 후 보호 시간이 끝남
- 최근 7일 안에 같은 상대와 매칭된 기록이 없음
- 동일 기기·IP·결제 수단과 연결된 계정이 아님
- 최근 활동 기록이 있음
- 제재 중이거나 검토 보류 상태가 아님

### 13.5 Match Limits

- 계정당 동시에 1개 매치만 진행
- 하루에 방어자로 새로 매칭되는 횟수는 최대 1회
- 매치 종료 후 12시간 동안 신규 매칭에서 보호
- 같은 상대와 7일 이내 재매칭 금지
- 비정상적인 승리 이전(Win Trading) 패턴 자동 탐지

### 13.6 문제 세트 배정

도전자와 방어자에게 서로 다른 Variant Set을 제공한다.

- 동일 단원 구성
- 동일 문항 수와 배점
- 동일 목표 난이도
- 동일 제한시간
- 숫자·조건·선택지는 서로 다르게 구성
- 사전 난이도 보정을 완료한 세트만 사용

### 13.7 승패 결정

1. 난이도 가중 정답 점수
2. 고난도 문항 정답 수
3. 정답 문항에 사용한 실제 풀이 시간
4. 앞선 기준까지 같으면 방어자가 승리

도전자가 순위를 가져가려면 방어자보다 명확히 높은 성과를 기록해야 한다.

### 13.8 No-show 처리

| 상황 | 처리 |
|---|---|
| 도전자 No-show | 도전자 패배, 잠근 일수 차감 |
| 방어자 첫 No-show | 매치 무효, 도전자 일수 잠금 해제, 방어자 경고 |
| 최근 7일 안에 방어 No-show 2회 | 순위표에서 일시 숨김 |
| 서버 장애 | 양쪽 잔액과 상태를 매치 이전으로 복구 |
| 문제 오류로 공정한 판정이 어려움 | 매치 무효 또는 재시험 |

순위표에서 숨김 처리된 사용자는 공식 모의고사 또는 지정된 방어 절차를 완료한 뒤 복귀한다.

## 14. Sub Ranking Rank Takeover 정산

Rank Takeover에는 `refundChallengeDays`를 사용한다.

### 14.1 방어자 승리

- 도전자가 잠근 일수를 차감한다.
- 같은 일수를 방어자의 `refundChallengeDays`에 지급한다.
- 양쪽의 공개 순위는 그대로 유지한다.
- Sub 전체의 도전 일수 총합은 변하지 않는다.

### 14.2 도전자 승리

- 도전자와 방어자의 공개 순위를 서로 바꾼다.
- 도전자가 잠근 일수는 시스템에서 소각 처리한다.
- 방어자의 도전 일수는 차감하지 않는다.

### 14.3 페이백 조건과의 관계

신규 사용자는 도전 일수 29일로 시작하므로, 페이백 조건인 30일 이상을 만들려면
다음 중 하나가 필요하다.

- 다른 사용자의 도전을 방어하고 승리해 일수 획득
- 사전에 공개된 학습 보상 정책에 따라 도전 일수 획득

사용자에게 공개하지 않은 보상이나 관리자 재량 지급은 허용하지 않는다.

## 15. Main Ranking Rank Takeover 정산

Rank Takeover에는 `bonusAccessDays`를 사용한다.

### 15.1 방어자 승리

- 도전자가 잠근 추가 학습권을 방어자에게 이전한다.
- 공개 순위는 그대로 유지한다.
- Main 전체의 추가 학습권 총합은 변하지 않는다.

### 15.2 도전자 승리

- 도전자와 방어자의 공개 순위를 서로 바꾼다.
- 도전자가 잠근 추가 학습권은 시스템에서 소각 처리한다.
- 방어자의 추가 학습권은 차감하지 않는다.

### 15.3 잔액 변동 공식

$$
ClosingBonus = OpeningBonus + DefenseTransfers - DailyUse - ChallengeBurn - ShopBurn - ExpiryBurn
$$

Rank Takeover만으로는 새로운 추가 학습권이 생기지 않는다.

## 16. Main Ranking 랭크 상점

### 16.1 판매 원칙

- 결제 수단은 `bonusAccessDays`만 사용한다.
- 현금 환급, Gift Card, 외부 상품 또는 사용자 간 송금 기능은 제공하지 않는다.
- 구매와 동시에 원장(Ledger)에 기록한다.
- 이미 시작된 매치에는 Rank Shield를 소급 적용하지 않는다.

### 16.2 판매 아이템

| 아이템 | 가격 | 효과 |
|---|---:|---|
| Rank Shield 12H | 1일 | 12시간 동안 신규 방어 매칭에서 제외 |
| Rank Shield 24H | 3일 | 24시간 동안 신규 방어 매칭에서 제외 |
| Rank Shield 48H | 5일 | 48시간 동안 신규 방어 매칭에서 제외 |
| Match Review Pass | 1일 | 완료한 매치의 상세 분석 리포트 1회 열람 |
| Mock Insight Pass | 2일 | 공식 모의고사 심화 분석 리포트 열람 |

### 16.3 Rank Shield 이용 제한

- 7일 동안 최대 1회
- 한 시즌에 최대 3회
- 시즌 종료 72시간 전부터 구매 불가
- 여러 Rank Shield 동시 적용 불가
- Rank Shield 활성 중에는 다른 사용자를 공격할 수 없음
- 사용자가 직접 해제해도 사용한 일수는 반환하지 않음
- 이미 성립한 방어 매치에는 적용하지 않음

## 17. Main Ranking 재결제 제한

### 17.1 구매 차단 조건

$$
Blocked = MAIN \land (bonusAccessDays > 0 \lor lockedDays > 0 \lor activeMatch)
$$

다음 중 하나라도 해당하면 새 패키지 주문을 생성할 수 없다.

- `bonusAccessDays`가 1일 이상 남아 있음
- `lockedDays`가 1일 이상 남아 있음
- 진행 중 Rank Takeover가 있음

### 17.2 구매 허용 조건

```text
activeRanking = MAIN
bonusAccessDays = 0
lockedDays = 0
진행 중 Rank Takeover 없음
```

위 조건을 모두 만족할 때만 새 패키지 결제를 허용한다.

### 17.3 적용 지점

- 화면의 결제 버튼 비활성화
- 주문 생성 API에서 서버 검증
- 결제 Webhook 처리 단계에서 재검증
- 동시 요청을 막기 위해 트랜잭션 또는 원자적 조건 업데이트 적용

### 17.4 사용자 안내 문구

> 현재 Main Ranking에서 사용할 수 있는 추가 학습권이 남아 있습니다. 보유 학습권을 모두 사용하고 진행 중인 랭킹전을 마친 뒤 새 패키지를 구매할 수 있습니다.

## 18. 부정행위와 이의신청

### 18.1 탐지 항목

- 시험 중 App 이탈 또는 화면 전환
- 비정상적으로 짧은 응답 시간
- 동일 기기·IP에서 여러 계정 사용
- 정답·오답 패턴의 높은 유사도
- 고의 패배로 승리를 넘기는 Win Trading 패턴
- 문제 또는 정답 유출 정황
- 자동화 Tool 사용 정황

### 18.2 처리 절차

1. 검토 대상에 Review Flag 표시
2. 해당 매치, MMR, 잔액 반영 보류
3. 사용자에게 검토 사유와 자료 제출 기한 안내
4. 풀이 흔적, 계산 과정, 설명 자료를 제출할 기회 제공
5. 탐지 신호와 제출 자료를 함께 검토
6. 판정 전에는 경고 상태로 유지하고, 위반이 확인된 뒤 제재
7. 재심 신청 기회 제공

### 18.3 단계별 조치 예시

| 단계 | 조치 |
|---|---|
| 1회 경미한 위반 | 경고 및 해당 매치 무효 |
| 자료 미제출 | 이후 공식 모의고사 3회 참가 제한 |
| 반복 또는 조직적인 조작 | 랭킹 초기화, 부당하게 얻은 일수 회수, 계정 정지 |

부당하게 얻은 일수를 회수할 때는 기존 거래를 삭제하지 않고 취소·보정 거래를 추가하며,
사유를 사용자에게 안내한다.

### 18.4 자동 판정의 한계

자동 탐지 결과만으로 계정을 영구 정지하지 않는다.
운영자의 검토 없이 학습권을 임의로 소멸시키지 않는다.

## 19. 장애와 예외 처리

### 19.1 서버 장애

- 시험 시작·제출 기록과 장애 발생 시각을 비교한다.
- 공정한 결과를 확정할 수 없으면 매치를 무효 처리한다.
- 잠근 일수는 매치 이전 상태로 복구한다.
- 장애로 연속 학습 기록이 끊겼다면 출석 복구 절차를 제공한다.

### 19.2 문제 오류

- 오류 문항을 제외한 뒤 다시 채점할 수 있다.
- 순위가 달라지면 MMR과 매치 결과를 다시 반영한다.
- 이미 지급한 일수는 기존 기록을 삭제하지 않고 취소·보정 거래로 조정한다.
- 정정 내용과 영향을 받은 범위를 사용자에게 알린다.

### 19.3 결제·페이백 재시도

- 결제사 Transaction ID와 Payback ID를 Idempotency Key(중복 처리 방지 키)로 사용한다.
- Timeout을 곧바로 실패로 처리하지 않고 결제사에서 최종 상태를 확인한다.
- 지급 결과가 확정되지 않으면 `REFUND_REVIEW` 상태로 유지한다.
- 같은 결제 건의 페이백을 중복 실행하지 않는다.

### 19.4 동시 요청 처리

Rank Takeover 신청과 일일 이용 차감이 동시에 들어와도 잔액이 음수가 되어서는 안 된다.
서버는 조건부 업데이트와 Database Transaction으로 두 요청을 안전하게 처리한다.

## 24. 검수 시나리오

### 24.1 결제와 권리

1. 결제 승인 시 유료 29일과 도전 29일이 각각 한 번 발급된다.
2. 결제 웹훅을 재전송해도 두 번 발급되지 않는다.
3. Rank Takeover 패배 후 유료 이용일은 변하지 않는다.
4. 음수 잔액을 만드는 동시 요청은 거절된다.

### 24.2 페이백

5. `streakDays=30`, `refundChallengeDays=30`이면 심사로 이동한다.
6. 출석 29일이면 도전 잔액이 많아도 페이백하지 않는다.
7. 도전 잔액 29일이면 출석 30일이어도 페이백하지 않는다.
8. 같은 결제 건의 두 번째 지급 요청은 거절된다.
9. 도전 60일이면 추가 학습권 31일이 된다.

### 24.3 랭킹 노출

10. Sub 사용자는 Main 공개 목록에 나타나지 않는다.
11. Main 사용자는 Sub 공개 목록에 나타나지 않는다.
12. 캐시 갱신 중에도 두 목록에 동시에 나타나지 않는다.
13. 배치 중에는 임시 순위를 보여 주지 않는다.
14. Main 승격 후 MMR은 유지되고 Main 풀 순위만 새로 계산된다.

### 24.4 공식 모의고사와 MMR

15. 세 슬롯 중 한 응시만 MMR에 반영된다.
16. 연습 응시는 MMR 이력을 만들지 않는다.
17. `N=1`이면 MMR 정산을 보류한다.
18. 동점자는 평균 순위로 같은 실제 성과를 받는다.
19. 정산 후 MMR과 티어가 같은 거래에서 저장된다.

### 24.5 Rank Takeover

20. 다른 활성 랭킹 사용자끼리 매칭되지 않는다.
21. 잔액이 2일 미만이면 근거리 도전을 만들 수 없다.
22. 도전자 승리 시 순위 스왑과 일수 소각이 함께 완료된다.
23. 방어자 승리 시 일수 이전 총량이 보존된다.
24. 서버 장애 취소 시 잠금 일수가 복구된다.
25. 같은 상대와 7일 안에 재매칭되지 않는다.

### 24.6 재결제

26. Main 추가 학습권이 1일이면 주문 API가 거절한다.
27. 잔액은 0이지만 잠금 2일이면 주문 API가 거절한다.
28. 잔액·잠금이 0이어도 진행 중 매치가 있으면 거절한다.
29. 모든 조건이 0이고 매치가 없으면 주문을 허용한다.
30. 새 결제 완료 후 이름이 Main에서 제거되고 Sub에만 나타난다.
